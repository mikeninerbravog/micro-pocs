# Micro-POCs — Small experiments, measurable results

**Independent, reproducible software engineering experiments.**

[English](README.md) | [Português (Brasil)](README.pt-BR.md)

This public repository contains focused micro-proofs-of-concept. Each experiment isolates a technical idea, supplies runnable source code and tests, reports observations, and clearly states its limitations. The goal is to learn from measured behavior—not to advertise benchmark wins or production readiness.

## Experiments

| Experiment | What it tests | Run | Key finding |
|---|---|---|---|
| [01 · API Pagination](api-pagination/README.md) | OFFSET/LIMIT versus keyset cursor over SQLite and HTTP | `python3 certify.py --repeat 100` | Cursor-based queries performed better at deep offsets in the tested workload. |
| [02 · Async Logging](async-logging/README.md) | Buffered synchronous writes versus bounded asynchronous queue | `python3 poc.py certify --events 10000` | The asynchronous approach was slower and dropped events under saturation in the tested workload. |
| [03 · Caching](caching/README.md) | Direct indexed SQLite reads versus cache-aside, LRU and TTL | `python3 poc.py certify` | Cache-aside improved median latency and throughput under a hot-key workload, but not every latency percentile. |

## Quick start

Requirements: **Linux**, **Python 3.10+**, and the Python standard library. No cloud services, Docker, or third-party Python packages are required. Commands below run from the repository root.

```bash
git clone https://github.com/mikeninerbravog/micro-pocs.git
cd micro-pocs

# Pagination — start an HTTP server in a separate terminal
cd api-pagination
python3 poc.py init
python3 poc.py serve --port 8080
# In another terminal: python3 benchmark.py --repeat 100
# Or without a separate server: python3 certify.py --repeat 100

# Async logging (from repo root)
cd ../async-logging
python3 poc.py bench --events 100000
python3 poc.py certify --events 10000

# Caching
cd ../caching
python3 poc.py init --rows 100000
python3 poc.py bench --requests 100000
python3 poc.py certify
```

Each experiment has a detailed README with CLI options, methodology, expected results, and limitations. For Portuguese instructions, see [README.pt-BR.md](README.pt-BR.md).

## How to interpret the numbers

- **p50 / p95**: median and 95th-percentile observed operation duration.
- **Throughput**: completed or persisted operations per second; read the experiment definition before comparing.
- **Correctness**: independently checked invariants, response boundaries, loss/accounting, or result checksums.
- **PASS / FAIL**: acceptance checks for that *specific experiment*, not a production certification.
- **COMPLETE**: the bounded experiment concluded; it is not a claim of readiness for deployment.

Benchmarks depend on CPU, storage, Python version, dataset, process scheduling and workload distribution. Re-run locally before drawing operational conclusions. Results are descriptive rather than universal.

## Engineering scope

These are minimal demonstrations rather than reusable production libraries. No performance guarantee is implied. Every README explicitly states what's tested, what's not, and how to reproduce the outcome. A negative result is a valid experiment result.
